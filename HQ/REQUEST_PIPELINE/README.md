# Request / Capability Pipeline

A visible intake for proposals to use or build apps, plugins, skills, services, communication surfaces, automation, or other capabilities.

Minimal packet:
1. need/opportunity;
2. proposed tool/service;
3. expected benefit;
4. cost/account/privacy/transparency constraints;
5. smallest useful trial;
6. how results return to the repositories;
7. second-opinion/audit surface;
8. owner + next action.

Default: do the smallest reversible useful trial when low-risk and authorized; do not wait for Nathan merely to discuss ordinary implementation details. Escalate consequential spending, external commitments, irreversible publication, credential/security risk, or unclear licensing.

External systems such as Slack are transport/work surfaces, not archival authority: important results must be returned to an auditable repository surface.
