# Nathan Voice / Communication Model — Index and Authority

**Purpose:** control which voice-model documents may be used for active SAT/H(s)H repo work and which are reference-only.

## Current structure

### TRACK 1 — ACTIVE REPO WORK / NONFICTION

1. `Nathan_Nonfiction_Communication_Standard_v0.1.md`
   - **Status:** PROVISIONAL ACTIVE DRAFT
   - **Authority:** derived from direct Nathan instruction and verified/direct-source corpus; **not yet Nathan-approved as a final standard**
   - **Use:** communication with Nathan, repo coordination, technical discussion, directives, summaries, reconstruction prose planning

2. `Nathan_Formal_Scientific_Transfer_v0.1.md`
   - **Status:** PROVISIONAL TRANSFER SPECIFICATION
   - **Authority:** inferential; based on Nathan's nonfiction communication structure, not on a corpus of Nathan-authored formal scientific papers
   - **Use:** guide for converting Nathan's nonfiction reasoning/communication habits into formal scientific prose without importing informal surface mannerisms
   - **Important limitation:** no genuine Nathan-authored formal scientific sample has yet been supplied for calibration. This document describes what should be preserved during transfer, not yet the final surface style of a Nathan scientific paper.

### TRACK 2 — REFERENCE ONLY / CREATIVE + INFORMAL VOICE

3. `Nathan_Creative_Informal_Reference_v0.1.md`
   - **Status:** REFERENCE ONLY
   - **Authority:** corpus-based descriptive model
   - **Use:** creative writing, informal voice emulation, narrative analysis, historical style comparison
   - **Do not use as a style source for formal scientific writing or active repo documentation except where it identifies a cross-register structural habit explicitly imported by Track 1.**

## Legacy combined models

- `Nathan_Voice_Model_v7.md` — combined synthesis immediately preceding the split. Retained as provenance and a cross-track research record.
- `Nathan_Voice_Model_v6.md`, `Nathan_Voice_Model_v1.md`, `NATHAN VOICE ANALYSIS.txt` — earlier development history.

The legacy files are **not deleted or silently rewritten**. They record how the model developed and may contain useful observations not yet promoted into either active track.

## Authority rule

Direct Nathan correction outranks all model inference.

A document does not become a Nathan-approved voice authority merely because an assistant created or updated it. Until Nathan explicitly approves a version, it remains provisional.

Recommended version lifecycle:

- `v0.x` — working/provisional; open to substantial revision
- `v1.0` — first Nathan-approved active standard
- `v1.x` — backward-compatible clarification/addition
- `v2.0+` — material conceptual revision

Each active document should state its own status, authority, scope, and supersession relationship at the top.
