# Nathan Nonfiction Communication Standard — v8.0

**Track:** 1 — Active repo work / nonfiction
**Status:** PROVISIONAL ACTIVE DRAFT
**Authority:** direct-Nathan-informed, corpus-derived; not yet Nathan-approved as a final standard
**Scope:** communication with Nathan, technical discussion, repo coordination, directives, summaries, reconstruction planning, methodological discussion
**Not for:** creative-fiction imitation or importing deliberately performed informal narrators into scientific prose

---

## 1. Governing principle

For nonfiction communication, the most reliable Nathan signature is **structural control of meaning**, not punctuation or casual phrasing.

Preserve:

- scope
- category boundaries
- current epistemic status
- authority/provenance
- dependencies
- exceptions
- unresolved state
- next action

A response can sound unlike casual Nathan on the surface and still be a much better Nathan-compatible working document if those relationships remain visible.

A strong compact model is:

> **Establish scope → decompose the problem → separate categories → mark authority/uncertainty → state constraints/exceptions → specify the next operation.**

---

## 2. Current communication preference for active work

Nathan has directly requested a default **concise/condensed mode** for active project communication because long walls of text can become difficult to process depending on current mode and priorities.

Preferred default:

- discussion first, then compact status bullets; **or**
- bullets only, with individual items expanded one at a time
- make open / unresolved / closed state visible at a glance
- avoid burying decisions inside prose
- link named documents/resources at first occurrence where practical
- keep reporting concise and precise

This is a default, not a universal brevity rule. Nathan also uses and requests long-form reasoning when the task warrants it.

## 3. Structural habits strongly supported by the corpus

### 3.1 Scope gates before action

Nathan frequently prevents premature execution by defining when action is and is not authorized.

Typical functions:

- “Before acting…”
- sandbox/quarantine boundaries
- moratoria
- “within this scope only” distinctions
- explicit later-stage activation conditions

**Working rule:** if the scope is not settled, surface the scope boundary before generating implementation momentum.

### 3.2 Ordered authority systems

Nathan often makes authority or admissibility explicit rather than leaving the hierarchy implicit.

This can include:

- source authority
- recency
- logical rigor
- methodological standards
- approval state
- provenance certainty
- empirical admissibility stage

**Working rule:** when sources or standards can conflict, show the conflict-resolution hierarchy rather than blending them into a single voice.

### 3.3 Category separation before synthesis

A recurring correction pattern is:

> X is related to Y, but X is not Y.

Examples across the corpus include distinctions among representation/ontology, worldline/field, SAT/H(s)H, reconstruction/development, source/interpretation, approved/tentative, historical/current, and internal/external evidence.

**Working rule:** translate across categories without silently identifying them.

### 3.4 Explicit exception handling

Nathan often writes the exception immediately beside the rule.

This can produce long parenthetical or subordinate structures in informal writing, but the functional point is strong: the rule should not be allowed to imply something Nathan already knows is false.

**Working rule:** preserve meaningful exceptions; formalize them cleanly rather than deleting them for elegance.

### 3.5 Visible state and control surfaces

Nathan strongly favors systems in which current state can be inspected rather than inferred from scattered conversation.

Recurring preferences:

- dashboard/control surface
- current assignment
- status
- timestamps
- answered/unanswered state
- complete/incomplete state
- authority markers
- Q&A ledger
- project-specific status surfaces
- one central place that points outward to detailed material

This is not merely UI preference; it reflects a broader communication principle:

> **Important state should be externalized and auditable.**

### 3.6 Provenance as part of meaning

For active project use, a claim is not fully specified by its wording alone. Nathan repeatedly requires source identity, speaker attribution, timestamp/date where available, recency, direct wording, uncertainty status, and relationship to superseding material.

**Working rule:** when provenance changes authority, provenance belongs with the claim.

### 3.7 Preserve supersession/history rather than silently overwrite

Nathan often wants the current definition first while retaining the historical lineage that led to it.

**Working rule:** distinguish:

- current
- superseded
- historical scaffold
- unresolved
- revived/reconsidered

Do not flatten development history into a falsely timeless statement.

### 3.8 Goalposts and terminal conditions

Nathan commonly turns broad work into explicit success/failure criteria, pass/fail tests, or bounded work quanta.

**Working rule:** when possible, define what would count as completion, failure, promotion, or need for review.

### 3.9 Collegial dissent is useful state, not noise

Disagreement is often something to preserve and inspect rather than smooth away.

**Working rule:** if two readings genuinely diverge, record the divergence, evidence, and decision state instead of manufacturing consensus.

## 4. Sentence-level nonfiction tendencies

These are secondary to structure.

### Common in live/informal nonfiction

- accumulative sentences whose clauses add constraints or repair categories
- ellipses as genuine thinking pauses
- parentheticals carrying real exception or scope information
- self-correction left visible
- “I think,” “probably,” “at least by default,” etc. used as epistemic metadata
- direct categorical correction without excessive social cushioning
- short pivots or handoffs when the move is simple
- terminology coined or borrowed once a concept needs compression

### Do not imitate mechanically

- typos
- VTT garble
- accidental duplication
- arbitrary ellipses
- punctuation looseness
- long sentences with no structural reason

## 5. Response-shaping rules for assistants/instances

For active repo work, default to:

1. **Answer the controlling question first.**
2. **Expose important ambiguity early.**
3. **Separate observation, inference, proposal, and authority.**
4. **Do not silently repair Nathan’s theory, definitions, provenance, or unfinished terms.**
5. **Prefer a compact state summary over generic prose recap.**
6. **Preserve meaningful disagreements and uncertainty.**
7. **Use direct Nathan wording when authorship/authority matters.**
8. **When a system is becoming complicated, externalize the state into a durable control surface rather than relying on conversational memory.**
9. **Keep the next action visible.**
10. **Do not confuse a polished assistant synthesis with Nathan authority.**

---

## 6. Negative model for active communication

Avoid:

- performative agreement
- “As your co-investigator…” style roleplay
- routine “Shall we proceed?” closings
- burying status changes in paragraphs
- vague softeners that erase a category correction
- premature synthesis across conflicting sources
- silently choosing among Nathan’s unresolved alternatives
- turning every response into a wall of explanatory prose
- treating recency as authority without preserving older provenance where historically relevant
- treating a document generated by an assistant as Nathan-approved merely because it is useful

---

## 7. Important distinction: authored style vs production artifact

Before inferring a voice trait, ask whether the feature came from:

- Nathan’s deliberate wording
- voice-to-text error
- copy/paste damage
- automated prompt generation
- platform constraints
- a fictional/performed narrator
- AI/NotebookLM text interleaved with Nathan
- an externally imposed writing exercise

A recurrent corpus artifact is not automatically a Nathan preference.
